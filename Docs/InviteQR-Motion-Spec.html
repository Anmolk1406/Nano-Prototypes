01Pipeline

One normalised tilt vector drives everything. The sensor pipeline produces tilt = (x, y), both axes in −1…1. Both axes are then inverted, and every visual reads t = (−tilt.x, −tilt.y), so the card leans against the phone's tilt. It is computed once per frame and read by every layer. Nothing on this screen animates on a timer: with the phone still, the card settles flat and stays there.

Per frame, in order

// dt = seconds since last frame, capped at 0.1
rel    = attitude relative to reference
sample = { x: clamp(rel.roll°  / 30),
           y: clamp(rel.pitch° / 30) }

speed  = |sample − lastSample| / dt
idle   = speed < 0.35 ? idle + dt : 0
if (idle ≥ 0.3) {
  k    = 1 − 0.5^(dt / 0.45)
  bias += (sample − bias) · k
}
raw    = clamp(sample − bias)

a      = 1 − (1 − 0.14)^(dt · 60)
tilt  += (raw − tilt) · a

t      = { x: −tilt.x, y: −tilt.y }  // invert X and Y
// every formula from §04 on reads t

Fallbacks

  • No gyro (simulator, some Android devices): a demo sweep, phase += dt·0.55, raw = (sin φ, 0.8·cos 0.73φ). The two frequencies are incommensurate, so the sweep never visibly repeats.
  • Touch drag on the card: raw = (dx / 140, −dy / 140), clamped ±1. On release raw = 0 and the smoothing carries the card back to flat.
  • Reference pose: captured the first time the sensor starts, and kept across later starts. The prototype also has a manual Recenter in its test panel, which takes the current attitude as the new reference and resets the bias to 0. For RN, capture the reference each time the screen gains focus, so the card always opens flat however the phone is held.
Start and stop: the sensor and the frame loop run only while this screen is visible. Start them on focus and stop them on blur.

  • Sheen and iridescence sit on top of every card layer, the QR and the name included, with the iridescence above the sheen. Both add light to the finished card beneath them. Blending them against anything else, such as one layer or an empty canvas, gives the wrong colour.
  • Clip before mask. The bands are far larger than the card. Clip them to the card box first, then apply inv_card_mask, so the chrome's rounded corners and outer glow shape the light. Without the mask, a pale rectangle shows where the box extends past the rounded chrome.

If the layers are turned separately, their clips can drift apart under perspective and light can leak past the card's edge.

verify Perspective is derived, not measured. SwiftUI's rotation3DEffect sets m34 = −p / max(w, h), so p = 0.85 on a 409 pt card gives a camera distance of about 409 / 0.85 ≈ 481 pt. In every formula from here on, tilt.x and tilt.y mean the inverted value t from §02. tiltMagnitude = min(1, √(x² + y²)) is used by the depth scale, the sheen, the iridescence and the shadow radius, and is the same either way.

  • Wobble is an extra in-plane rotation of that one layer: tilt.x × 5° × layer.wobble (0.2 for the QR, 0.1 for the name).
  • Depth scale: nearer planes grow slightly as the card turns, 1 + (h / 600) · tiltMagnitude. It applies to image layers only, not the name.

React Native mapping

  • react-native-haptic-feedback: impactHeavy on press-in, impactLight on press-out. It has no intensity control, so the release will be slightly stronger than 0.4.
  • For exact intensities, use a small native module calling UIImpactFeedbackGenerator.impactOccurred(intensity:).
  • Android: HapticFeedbackConstants.VIRTUAL_KEY for press-in and KEYBOARD_TAP for press-out, or VibrationEffect.createOneShot(10, amplitude) where amplitude is supported.
  • Respect the app-wide haptics setting: every call is gated on it.

11React Native notes

  1. Sensor on the UI thread: useAnimatedSensor(SensorType.ROTATION, { interval: 8 }) from Reanimated 3. Keep the whole pipeline in worklets so tilt never crosses the bridge.
  2. Relative pose: store the first quaternion as the reference and multiply each reading by its inverse, then read roll and pitch. Subtracting Euler angles also works inside ±30°, but drifts near the edges.
  3. Frame loop: run the step in useFrameCallback with the real dt, so smoothing and recentring behave the same at 60 and 120 Hz.
  4. Transforms: [{ perspective: 481 }, { rotateY: yaw }, { rotateX: pitch }, { rotateZ: roll }] on the card wrapper. RN applies them right to left, which matches the order in §04.
  5. Light bands and masks: use React Native Skia. A LinearGradient in a large Rect with blendMode="plus", clipped by an Image mask of inv_card_mask. Draw the card layers and the bands into one Skia canvas, then apply the 3D transform to that canvas's wrapper. Blending and clipping then happen in the card's plane, and nothing leaks outside the card at an angle.
  6. Springs: SwiftUI's response/dampingFraction maps to Reanimated as stiffness = (2π / response)² and damping = 2 · ζ · (2π / response), with mass 1.
  7. Assets are exported at 3× the frames listed: inv_bg, inv_frame, inv_panel, inv_qr, inv_card_mask, inv_star_l, inv_star_r, ic_close, ic_copy, ic_share.
// Reanimated sketch: the tilt worklet
const rot = useAnimatedSensor(SensorType.ROTATION, { interval: 8 });
const tilt = useSharedValue({ x: 0, y: 0 });
const s = useSharedValue({ ref: null, bias: {x:0,y:0}, last: {x:0,y:0}, idle: 0 });

useFrameCallback(({ timeSincePreviousFrame }) => {
  'worklet';
  const dt = Math.min(0.1, (timeSincePreviousFrame ?? 16.7) / 1000);
  const { roll, pitch } = relativeTo(s.value, rot.sensor.value); // quaternion × ref⁻¹
  const clamp = v => Math.max(-1, Math.min(1, v));
  const sx = clamp(roll * 57.2958 / 30), sy = clamp(pitch * 57.2958 / 30);
  const speed = Math.hypot(sx - s.value.last.x, sy - s.value.last.y) / dt;
  const idle = speed < 0.35 ? s.value.idle + dt : 0;
  let { bias } = s.value;
  if (idle >= 0.3) {
    const k = 1 - Math.pow(0.5, dt / 0.45);
    bias = { x: bias.x + (sx - bias.x) * k, y: bias.y + (sy - bias.y) * k };
  }
  s.value = { ...s.value, bias, last: { x: sx, y: sy }, idle };
  const a = 1 - Math.pow(1 - 0.14, dt * 60);
  const rx = clamp(sx - bias.x), ry = clamp(sy - bias.y);
  tilt.value = { x: tilt.value.x + (rx - tilt.value.x) * a,
                 y: tilt.value.y + (ry - tilt.value.y) * a };
});
// Invert X and Y: every visual reads t, not tilt.
const t = useDerivedValue(() => ({ x: -tilt.value.x, y: -tilt.value.y }));

13QA checklist

  • Phone held still for 0.3 s: the card starts easing back to flat and is most of the way there about 1 s later, with no snap.
  • Right edge of the phone tipped away (inverted axes): the card's right edge comes toward you, the QR drifts left about 2.4 pt, the panel drifts right about 1 pt, and the sheen slides right.
  • At rest, the iridescence is invisible and the sheen is faint (about 0.095).
  • At any angle, no light shows outside the chrome silhouette, including at the corners.
  • Share button: the heavy tick lands on touch-down, before the finger lifts, and a light tick follows on release.
  • Leaving the screen stops the sensor: check battery or CPU in the profiler.
  • Reduced Motion on: consider freezing tilt at 0 (the prototype doesn't yet).
